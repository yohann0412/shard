A shared run that fails tests is not a fair speed comparison: failures that wait for a timeout slow it down, and serial groups that stop at a failure speed it up.
- Their test phase is only 24.9s. Outside the test phase, isolate@4 spends 21.1s (starting Postgres, copying the database, booting one app per worker, Playwright start-up, teardown) against 8.2s for theirs; on a run this short that difference decides the wall time, so the test-phase column is the fairer one, and a longer suite the better test.
